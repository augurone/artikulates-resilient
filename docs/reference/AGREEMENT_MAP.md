## Resolve a change in order

1. Identify the producer, consumer, source identity and failure owner. Separate
   established evidence, contradictions and what remains unknown.
2. Read the applicable language clauses and supporting laws. State the actual
   observable contract: values, absence, identity, reads, calls, effects,
   iteration, completion and failure order where relevant.
3. Locate the current evidence owner and consumer. TypeScript annotations add
   requirements; generated guards and lint findings add no missing proof.
4. Select an admitted policy outcome, then its grammar and placement. An exact
   local exception must have the semantic reason required by Policy P-03.
5. Exercise the behavior and the unsupported boundary through the actual path.
   For a rewrite, compare native, raw and fixed execution as well as lint.
   State work/storage bounds when sharing or retaining analysis work changes.

The [engineering guides](../engineering/README.md) describe current ownership
and acceptance. The [feature review](../engineering/feature-review.md) records
missing surfaces. Essays supply design rationale; historical plans supply
context. They do not create additional APIs, product support or test gates.
